**含义**：这些功能代码写好了但没塞演示数据。**它们是很好的改造练习素材**——比如给 `pms_comment` 造几条评价数据，就能把商品评价功能跑起来。

### 2. 命名规律（记住这个，看表名就能猜用途）

- 表名前缀 = 业务域（`pms_` 商品 / `oms_` 订单 / `sms_` 营销 / `cms_` 内容 / `ums_` 用户）
- `_relation` 后缀 = **多对多中间表**（如 `ums_role_resource_relation`）
- `_log` / `_history` 后缀 = 日志或历史流水表（只追加，不修改）
- `_setting` 后缀 = 配置表（通常只有 1 行）
- 通用字段：`delete_status`（逻辑删除）、`create_time` / `modify_time`

### 3. 最该先吃透的 10 张

`ums_admin` · `ums_resource` · `ums_role` · `ums_member` · `pms_product` · `pms_sku_stock` · `pms_brand` · `pms_product_category` · `oms_order` · `oms_order_item`

### 4. 三个值得在面试里讲的设计

1. **商品 / SKU 分离** —— 展示单位 vs 库存单位，库存扣在 SKU 上并用 `lock_stock` 预占
2. **订单做快照** —— `oms_order_item` 冗余商品名称/图片/价格，`oms_order` 冗余收货地址。**交易凭证必须冻结在那一刻**
3. **权限动态化** —— `ums_resource.url` 让权限与代码解耦，改权限不用改代码、不用重启
